## 3. 必须一起写明的三条限定（否则这句 SUCCEEDED 会被读过头）

### 3.1 40 个未比对点：全部是时钟门锁存器，且**被 collapse 覆盖**

```
40 Unmatched points (0 reference, 40 implementation)
  Impl LATCG  i:/WORK/sar_digi_paper_core/u_calib_ctrl/clk_gate_accumulator_reg/latch
  …（40 条同形）
```

设置里已有 `set_app_var verification_clock_gate_hold_mode COLLAPSE_ALL_CG_CELLS`，
含义是**把每个时钟门折叠成"时钟 ∧ 使能"的 AND 模型再比对** ——
所以这 40 个锁存器**不是"漏掉"，而是"用折叠模型覆盖"**。
但它确实是**未按锁存器逐点比对**，报告里必须这样写。

### 3.2 **形式验证不证明 tie 网络的值**——这是本轮最重要的限定

Formality 自己报：

```
Warning: 0 (5) undriven nets found in reference (implementation) design (FM-399)
```

**参考侧 0 个无驱动网，实现侧 5 个。** 换句话说：
等价性是在**工具对无驱动网的默认处理**下成立的——tie 的值是**被假定**的，不是被证明的。
结合此前已知的 `HFSNET_8` 根网络无驱动，这条正好对上：
**LEC 通过，不等于 tie 网络的值被独立确认。**

（附注：我另写的一版"无驱动网"扫描器报出 179 个名字，但它是**粗糙口径**——
把形如 `.CLK(...)` 的**形参名**也算了进去，因此**不外推**；以 Formality 的 5 为准。
这条记录在此，防止后人误用那个 179。）

### 3.3 端口比对点 146 与顶层端口数 178 的账**没有闭合**

`fc_area.rpt` 报顶层端口 178；Formality 的 Port 比对点是 **146**；
另有 `30 Matched primary inputs, black-box outputs`、`0(0) Unmatched reference(implementation)`。

**本轮没有把 178 → 146 的差额逐项追出来，因此不解释、不猜测。**
列为 V1 的遗留子项（V1-a）：把两边的端口表逐名取出来对差。
