# 独立核查 V2/V3-a：交付网表的独立门级功能探测

**跑于** 2026-09-19　**产物** `/tmp/v2ind2/`（tb_indep.sv、build.log、run.log）
**方法**：**不使用设计者的任何 testbench**。从**网表自己的顶层端口表**自动生成一个自检测试台：
驱动所有输入、跑时钟与复位、然后对**每一个输出**以及**四个内部探测点**做 `$isunknown` 检查，
并打印自己的判定行。编译配方与被核查方 GLS 一致（`smic18.v` 单元模型 + 交付网表，零延迟）。

## 2. 这条结论回答了什么

| 问题 | 答案 |
|---|---|
| 交付的布线后网表**能不能仿真**？ | **能**——独立编译 + 运行 rc=0，无 X |
| 无驱动 tie 根网络（`HFSNET_8` 等 5 个，Formality FM-399）**会不会把 X 灌进设计**？ | **不会**（在这套单元模型下）——`u_srm_residue.rst_n` / `u_calib_ctrl.rst_n` 实测**不是 X** |
| 之前"交付网表功能从未判定"的空洞？ | **部分补上**：可仿真性已证；**功能正确性仍未判定**（见 §4） |

**⇒ 这条结果缓和了（但没有消除）此前"网表自身不自洽"的担忧**：
在仿真里它**不产生 X**，因为无驱动的 `z` 在这套单元模型里被解析成了确定值。
但**常量的值仍然没有被网表规定**——它是靠工具/模型的解析行为落定的，不是被写明的。

## 3. 必须一起记录：本工具自己错了三次

| 版本 | 错在哪 | 症状 | 修法 |
|---|---|---|---|
| v1 | 只从**模块头**解析方向声明（真实声明在模块体里） | 27 个真输入被判成输出、悬空 ⇒ **假报 17 个 X** | 改为解析模块体内的 `input/output` 行，遇到第一个实例即停 |
| v2 | 连线名没剥位宽 | `.[19:0] raw_bits_i(...)` ⇒ 语法错 | 加 `nm()` 剥 `[19:0]` 前缀 |
| v3 | 初始化与检查语句也没剥位宽 | `[19:0] raw_bits_i = 0;` ⇒ 语法错 | 初始化/检查统一用 `nm()` |

**v1 那次假报是"没有对照就会得出错误结论"的又一例**：17 个 X 全是我的悬空输入造成的。
真正有意义的信号（四个内部探测点）在 v1 里其实已经**没有**报 X，但当时不能采信。

## 4. 本轮**没有**证明的（下一轮）

1. **功能正确性**：本测试只证明"无 X"，**没有比对任何期望值**。
   真正的功能核查需要：自写激励 + 自写参考模型（金模型）逐笔比对。
2. **无驱动 tie 的机制**：为什么 `z` 会解析成确定值？**未做对照**。
   可判真假的对照实验：把 `HFSNET_8` 强制为 `1` 与强制为 `0` 各跑一次，
   若输出行为不同 ⇒ 值确实影响功能；若相同 ⇒ 说明该 tie 在本场景不被敏感路径使用。
3. **`calib_done` 是否会在合理激励下变 1**：本测试没有跑到标定完成。
