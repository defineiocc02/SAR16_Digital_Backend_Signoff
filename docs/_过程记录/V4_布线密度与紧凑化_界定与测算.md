## 1. 为什么布线看起来"散"：一个参数

`scripts/fc_pnr_paper_core.tcl`：

```tcl
set UTIL 0.55
initialize_floorplan -core_utilization $UTIL
```

交付报告实测：

| 量 | 值 | 来源 |
|---|---|---|
| 单元总面积 | 102300.11 µm² | `fc_area.rpt` Total cell area |
| 核心/块面积 | 184066.34 µm² | `fc_util.rpt` Total Area |
| **利用率** | **0.5558** | `fc_util.rpt` Utilization Ratio |
| 单元数 | 3626 | `fc_area.rpt` Number of cells |
| 布线溢出 | **2.52 %** 的 GRC | `fc_congestion.rpt` Both Dirs |

**⇒ 单元只占核心面积的 55.6 %，约 44 % 是空行。这不是布线失败，是 `UTIL` 这个数。**

**同一份报告也说明它不能白压**：55 % 利用率下已经有 **2.52 %** 的全局布线单元溢出，垂直方向更差。**所以"能压到多少"必须实验定，不能拍。**

## 2. 紧凑化的算术空间（只是算术）

把 `UTIL` 当作目标利用率，所需核心面积 = 单元面积 / 目标：

| 目标 `UTIL` | 所需核心面积 µm² | 相对当前缩小 | 边长缩放 |
|---|---|---|---|
| 0.60 | 170500 | **7.4 %** | ×0.962 |
| 0.65 | 157385 | **14.5 %** | ×0.925 |
| 0.70 | 146143 | **20.6 %** | ×0.891 |
| 0.75 | 136400 | **25.9 %** | ×0.861 |

⇒ 从 0.55 提到 0.70，面积上约可省 **20.6 %**，边长约 ×0.891。**这是面积算术，不是"能收敛"的结论。**

## 3. 实验该怎么跑（下一轮照此执行）

**单变量**：只改 `set UTIL`，其余一字不动（RTL/SDC/NDM/deck 都不动）。

| 步骤 | 命令 | 判据 |
|---|---|---|
| 1 | 以 `UTIL=0.65`（或 0.70）重跑 `bash scripts/run_pnr_paper_core.sh` | 三个阶段产物齐全，不看返回码 |
| 2 | `report_utilization` / `report_area` / `report_congestion` | 实测利用率、单元面积、**GRC 溢出** |
| 3 | 重跑 STA | **slow clk slack 仍为正**（当前 +0.7947 ns） |
| 4 | 重跑 DRC + LVS | DRC 结果数与 **LVS 短路仍为 0** |
| 5 | 与 v5.1 基线逐项列表对比 | 得到"密度—拥塞—时序"三方权衡 |

**必须一起报的量**：利用率、GRC 溢出、slow slack、DRC 结果数、LVS 短路口径。**只报面积变小是不合格的。**
