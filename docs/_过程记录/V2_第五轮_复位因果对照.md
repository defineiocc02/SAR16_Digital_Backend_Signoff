# 独立核查 V2 第五轮：**修正版对照——tie 根的值直接决定两个块是否被复位锁死**

**跑于** 2026-09-19　**产物** `/tmp/v2e/`（`tb_ctl.sv`、`build_0/1.log`、`run_0/1.log`）
**改动**：第 4 轮的对照 force 错了对象（打在子模块端口上），本轮 force 在**真正起作用的
五个父层根网络** `HFSNET_120…124`（以及子模块端口作为冗余），并修正了上一轮那个
"把参数本身算进差异"的坏比较器。

---

## 1. 结果

| 根网络被 force 为 | `rstn_calib` | `rstn_srm` | `busy` | `done` | `total` |
|---|---|---|---|---|---|
| **0** | **1** | **1** | 0 | 0 | 0 |
| **1** | **0** | **0** | 0 | 0 | 0 |

**⇒ tie 根的值直接、完全地决定两个子模块的复位：**
- 根 = 0 → 反相器 → `rst_n = 1` → **复位解除**
- 根 = 1 → 反相器 → `rst_n = 0` → **复位常驻**

而交付网表**自己解析出来的根值是 1**（第 5 轮实测 `HFSNET_124=1`）
⇒ **交付网表按原样仿真时，两个块被复位锁死。因果链由本轮对照闭合。**

## 2. 这条结论的分量

| 项 | 状态 |
|---|---|
| 「交付网表的主功能被一条**网表没有定义值**的 tie 链锁死」 | **已由对照实验证实**（force 0/1 → 复位解除/常驻，一对一的因果） |
| 这条链是 `HFSNET_120..124 → HFSINV → HFSNET_119 → rst_n` | 第 11 轮定位 + 第 5 轮值实测 + 本轮对照 |
| 可修 | 是：**重新导出网表**，让常量根有确定值（或在交付前把它写成 `1'b0`） |

**这是一个可复现、有因果对照的交付缺陷**，不是推测。

## 3. 但还有一个**没解决**的问题（不掩盖）

**即使把根 force 成 0、复位解除，`busy / done / total` 仍然是 0** ——
说明我给的激励**仍然没有把 SRM 估计器跑起来**。所以：

- 复位锁死是**功能无法被激励的一个原因**（已证）；
- 但它**不是唯一原因**（已证：解除复位后仍然不动）；
- 我的**激励/协议仍然不对**，这一项**本轮没有解决**。

第 4 轮那份"tie 两值无差异"的记录，现在有了正确的解释：
**当时 force 的对象不对**，所以两个值下 `rst_n` 都是 0，自然无差异。**该记录作废，以本轮为准。**
