# SAR16 后端 · 接手第 10 轮：交付网表与版图不一致 —— 最后一个 LVS 错误的真因

**时间**：2026-09-18 21:33–21:52　**性质**：诊断 + 单变量修复实验（设计/RTL/SDC/deck 一字未改；所有实验产物写在 `/tmp/lvs10`，项目树零写入）

---

## 1. 一句话结论

第 9 轮把残差收敛到"**唯一一条错误网 = VDD**"之后，本轮沿着这条线挖到底：

> **交付的 P&R 网表里，常量 tie 是用 85 个真实反相器（`HFSINV_*`）从一根
> `HFSNET_8` 造出来的，而 `HFSNET_8` 在整个 `.v` 里没有任何驱动。
> 两个最大子模块的 `rst_n` 也被接到同样没有驱动的 `HFSNET_119` 上。
> 版图里既没有 `HFSNET`、也没有这些 tie 网络 —— 版图是按常量传播后直接接到电源轨的。
> 所以这不是硅的问题，是「交付出去的网表没有描述它自己的版图」。**

## 2. 证据链（全部是读文件读出来的，不是推断）

### 2.1 tie 网络的结构

```verilog
// sar_digi_paper_core_pnr.v
CLKINVX3 HFSINV_106_588   ( .A ( HFSNET_8 ) , .Y ( HFSNET_4 ) ) ;
CLKINVX4 HFSINV_246_605   ( .A ( HFSNET_8 ) , .Y ( HFSNET_6 ) ) ;
INVX3    HFSINV_15018_625 ( .A ( HFSNET_8 ) , .Y ( HFSNET_9 ) ) ;
```

| 项 | 实测 |
|---|---|
| `HFSINV_*` 实例（Verilog / CDL） | **85 / 85** |
| 它们的 `.A` | 全部是 `HFSNET_8` |
| 它们的 `.Y` | `HFSNET_4`、`HFSNET_6`、`HFSNET_9` … |
| `HFSNET_8` 的驱动 | **没有**（全文件无 `assign` / `wire` / 任何 `.Y(HFSNET_8)`） |
| Verilog 里 `HFSNET` 出现的位置 | 实例连接 1830 处、端口声明 8 处、模块端口表 8 处；**无一处是驱动** |

**所以 `HFSNET_8` 才是那根"常量根"，其余 `HFSNET_*` 都是它的反相副本。**
版图侧 `SN` 引脚落在 **VDD** 上，而 `HFSNET_4` 正是 `HFSNET_8` 的反相输出
⇒ **`HFSNET_8` 的逻辑值是 0（VSS），反相后 `HFSNET_4 = 1 = VDD`，两边自洽。**

### 2.2 两个最大子模块的复位也是这个坑

```verilog
sar_calib_ctrl_serial_20_30_16_32_5_256_1_1 u_calib_ctrl (
    .clk ( ctosc_gls_0 ) , .rst_n ( HFSNET_119 ) , ...
srm_residue_estimator_...                    u_srm_residue (
    .dec_clk ( dec_clk ) , ... .rst_n ( HFSNET_119 ) , ...
```

而**顶层 RTL 写得清清楚楚**（`rtl/sar_digi_paper_core.sv`）：

```systemverilog
input  logic rst_n,   // asynchronous, active low, common to both domains
...
) u_calib_ctrl  ( ... .rst_n (rst_n), ... 
) u_srm_residue ( ... .rst_n (rst_n), ...
```

`HFSNET_119` 同样**没有任何驱动**，顶层 `rst_n` 端口在 P&R 网表里**一次都没被用到**。

**这条比 LVS 重要得多**：拿这份 `.v` 做门级仿真，两根根常量网是悬空的，
`rst_n` 与所有 tie 都是 `x`；而版图按常量传播接到了电源轨。
**网表与硅在这一项上不一致，且网表自身不自洽。**

### 2.3 版图侧相反

| 文件 | `HFSNET` 出现次数 |
|---|---|
| `pnr/out/sar_digi_paper_core_pnr.v` | 1841 行 |
| `calibre/lvs/sar16.cdl`（v2lvs 产物） | 1627 行 |
| `calibre/lvs/svdb/sar_digi_paper_core.sp`（**版图抽取**） | **0** |
| `HFSINV` 在版图抽取网表里 | **0** |

版图把 `HFSINV` 那一级常量传播掉了，负载直接接电源轨 —— 这是**正确且常规**的 P&R 行为。

## 3. 修复实验：单变量，做了一次，结论是"不能那样修"

对 `.v` 的**副本**做最小修复，然后重跑 v2lvs + LVS（黑盒 + `INJECT LOGIC NO`）：

| 尝试 | 改法 | v2lvs | LVS 结果 |
|---|---|---|---|
| 第 1 版 | 端口表换行丢逗号 → **语法错误** | **rc=1，无 CDL** | 未跑 |
| 第 2 版 | 把 `HFSNET_*` **全部**改成 `1'b1` | rc=0，CDL 里 `HFSNET = 0` | 仍 INCORRECT，VDD 变成 **637 vs 2063** |

**第 2 版把 VDD 连接数从 161 抬到 2063 = 改错了**：`HFSNET_8` 是常量根，
其余 `HFSNET_*` 是经过 85 个反相器的**反相副本**，全接到 VDD 等于把 85 个反相器
的输出也短到 VDD。报告给出的反例一眼可辨：

```
X7/X184  CLKINVX3            XHFSINV_6951_589  CLKINVX3
  Y: VDD                       Y: VDD
  A: 300                       ** no similar net **
  ** VDD **                    A: VDD
```

**正确的修法只有两种**（本轮已确定、下一轮执行）：

1. **只把没有驱动的"根"网络接常量**（`HFSNET_8` → `1'b0`，`HFSNET_119` → 待定），
   让 85 个 `HFSINV` 通过真实反相器把值传下去；
2. **更根本：让网表重新导出以匹配版图** —— 既然版图已做常量传播，
   `.v` 就不该再带 `HFSINV` 与 `HFSNET`。这也是交付件应该有的样子。

> 判据提醒：这一轮证明"**把开关全拧到一边**"不是修复，是另一个错误。

## 5. 本轮新增的工具坑

1. **端口表换行必须把逗号留在行尾**。第一版自动换行把逗号丢了，v2lvs 报
   `syntax error: file:... line:154 token:residue_valid`。
   **判据是"输出文件不存在"，不是返回码**（第一次只看了 rc）。
2. **`grep -c` 在 PowerShell 里管道会变成 bash 管道**（内层双引号被吃掉）。
   本轮又踩了一次，浪费两次调用。**远端只跑 scp 上去的脚本。**
3. **探针必须自带对照**。GDS 结构探针没有对照时"看起来"给出结论，
   加上对照（`NAND2XL` 等）后立刻自证无效。
