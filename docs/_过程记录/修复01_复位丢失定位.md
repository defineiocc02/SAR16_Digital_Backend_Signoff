# 修复日志 01：复位丢失定位到 **P&R 阶段**，机制指向「库内无 tie cell」

**日期**：2026-09-19 ｜ **依据**：独立核查发现 1（子模块复位锁死）

---

## 1. 丢失发生在哪一级：**P&R，不是综合**（对照见下）

| 阶段 | 两个子模块的 `.rst_n` | `HFSNET` 行数 |
|---|---|---|
| RTL（意图） | `.rst_n(rst_n)` | — |
| **DC 综合网表** `mapped_ss/…_netlist.v` | **`.rst_n(rst_n)`** ✅ | **0** |
| **布线后网表** `pnr/out/…_pnr.v` | **`.rst_n(HFSNET_119)`** ❌ | **1841** |

**⇒ DC 交出来的网表里复位是好的、常量网络一个都没有；是 FC 的 P&R 把它变成常量的。**
修复的落点是**P&R 阶段**，不是 RTL、不是 SDC、不是综合。

## 2. 不是 case analysis 造成的

三份约束（`constraints/*.sdc`、`pnr/out/*_pnr.sdc`）里：

```
set_case_analysis / set_constant / set_disable  →  一处都没有
rst_n 相关只有：set_false_path -from [get_ports rst_n]
                set_input_transition -min 0 / -max 0.2 [get_ports rst_n]
```

**⇒ 没有任何一处把 `rst_n` 声明成常量。所以不是"约束把它钉死了"。**

## 3. 真正的机制线索：**库里没有 tie cell**

FC 的日志里有这一条：

```
Warning: No tie cell is available for constant fixing. (OPT-200)
```

含义：FC 在优化期需要把某个常量接到负载上，**但 NDM 里没有 tie 单元可用**。
没有 tie cell 时，工具只能用**反相器从常量造常量**——这正是网表里那 85 个
`HFSINV_*`（`.A(HFSNET_8)` → `.Y(HFSNET_4/6/9/…)`）的形态。

**而这些"常量根" `HFSNET_120…124` 在写出的网表里没有任何驱动。**
两者对得上：**常量是 FC 内部造出来的，写 netlist 时根节点没被落地。**

## 4. 下一步（按这个顺序做，每步都能判真假）

| # | 动作 | 判据 |
|---|---|---|
| 1 | 查 NDM 里到底有没有 tie/constant 单元可被 `connect_tie_cells` 用 | 有 ⇒ 配它；没有 ⇒ 走第 2 条 |
| 2 | 把常量接到 **PG 轨**（而不是造反相器链）：`connect_tie_cells -tie_off` 或等价的常量处理选项 | 重跑 P&R 后 **`HFSNET` 行数为 0** |
| 3 | 重跑后**重新做 LEC**（RTL ↔ 新布线后网表） | 0 failing，且 **FM-399 的无驱动网数从 5 变 0** |
| 4 | 重跑门级仿真（复位序列 + SRM 计数） | `busy` 抬起、`total=22 / shortfall=0` |
| 5 | LVS | 短路仍为 0；端口仍 178 |

**第 3 步的关键判据是 FM-399 那个"实现侧 5 个无驱动网"变成 0** ——
它正是本轮修复要消掉的东西，且是**可自动核对**的。

## 5. 本轮的边界

- **只做了定位，没有改任何文件**（RTL/SDC/deck/网表一律未动）；
- 「无 tie cell 导致常量处理异常」是**有日志支撑的机制线索**，
  但**尚未做"补上 tie cell 后常量消失"的对照实验** ⇒ 不宣称已确证；
- 第 2 条动作需要重跑 P&R，而该 stage 脚本会 `rm -rf $PRJ/pnr`，
  **必须在副本工程/独立输出目录上做**，不能动现有交付产物。
