# 独立核查 V3：门级仿真可用性核查（交付网表到底跑过什么）

**方法**：读被核查方遗留的门级仿真产物与其 runner 脚本，不改动任何文件。
**依据**：`pwr_gls/build.log`、`pwr_gls/run.log`、`pwr_gls/run.out`、`scripts/run_tb_paper_core.sh`

---

## 1. 关键发现：**它跑的是交付的布线后网表，但不是功能核查**

`pwr_gls/build.log` 第 1 行的 vcs 命令行给出的文件清单：

```
/home/<user>/Project/DESIGN/14BIT_ADC/smic18/digital/sc/verilog/smic18.v   ← 标准单元仿真模型
/home/<user>/sar16_work/proj_paper_core/pnr/out/sar_digi_paper_core_pnr.v  ← 布线后网表
/home/<user>/sar16_work/proj_paper_core/tb/tb_sar16_core_pwr.sv            ← 测试台
vcs -full64 -sverilog +v2k -timescale=1ns/1ps +nospecify +notimingcheck
```

**这是好消息**：门级仿真确实编译的是**布线后网表**，不是综合网表。

**但它不是功能核查**，三条证据：

| 证据 | 含义 |
|---|---|
| `+nospecify +notimingcheck` 且 TB 自称 `gate-level activity TB, zero-delay by design` | **零延迟、无时序检查**——不是时序仿真 |
| `run.log` 的全部产出是 `SAIF_WRITTEN core_operating.saif` / `core_calib.saif` | TB 的目的是**产出功耗活动率文件**，不是判定功能 |
| 结束行是 `TB_CORE_PWR done: calib_mode_en=1 calib_done=0` 后 `$finish` | **没有任何 PASS/FAIL 判定**；`calib_done=0` 只是被**打印**出来，没人判它 |

**⇒ 交付的布线后网表从未跑过带判定的功能仿真。** 这与交付 README 自述"未做：带 SDF 的门级仿真"是一致的，
但更准确的说法是：**连不带 SDF 的功能级门级仿真也没有判定过**——那一次 GLS 只服务功耗标注。

## 2. 与 V1 合起来看，"功能"的覆盖现状

| 层 | 有什么 | 是否功能核查 | 时点 |
|---|---|---|---|
| RTL | `tb_sar16_paper_core.sv` + `run_tb_paper_core.sh`（含 Phase-2 自检、差分运行、`p_round_fold_guard`） | **是**（设计者自写） | v4.x |
| RTL ↔ 综合网表 | Formality | 是（等价性） | 08:04 |
| RTL ↔ **交付布线后网表** | 原先**没有** → **本轮 V1 补上，SUCCEEDED** | 是（等价性） | 09-19 17:05 |
| **交付网表门级功能仿真** | `pwr_gls`（零延迟、只为 SAIF、无判定） | **否** | 08:53 |
| SDF 时序仿真 | 没有 | **否** | — |

**⇒ 两种意义上的空洞：(a) 交付网表的等价性原先没查（V1 已补）；(b) 交付网表的门级功能从未判定。**

## 3. 尚未确定、下一轮要做的（V3-a / V2）

1. **无驱动 tie 网络在仿真里的实际后果**：`HFSNET_8` 等无驱动网在 Verilog 里是 `z`，
   进单元输入即 `x`。现有 `run.log` **没有报任何 X 相关告警**，但该 TB 也不检查功能，
   所以**"没报 X"不能读成"没有 X"**。需要用**自己的**带判定 testbench 去实测。
2. **`calib_done=0`**：TB 在 30 000 clk 后打印 `calib_done=0`。**本轮不判定它是否正常**
   ——需要先读 `tb_sar16_core_pwr.sv` 的激励序列与 `sar_calib_ctrl_serial` 的完成条件，
   否则就把"激励没跑完"误判成"功能不对"。
3. **可复现的编译配方已拿到**（上面那三行 + 开关），下一轮可以直接用它起一个**独立**的
   门级功能仿真：自己写激励与 checker，不沿用 `tb_sar16_core_pwr.sv` 的"只产 SAIF"模式。
