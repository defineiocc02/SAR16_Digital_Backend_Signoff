# 独立核查 V2 第四轮：**交付网表把两个最大子模块永久按在复位里**（实测）

**跑于** 2026-09-19　**产物** `/tmp/v2d/`（`tb_probe.sv`、`build.log`、`run.log`）
**方法**：自生成探测测试台，驱动 `clk`/`dec_clk`/`rst_n` 与 `srm_start`，在 5 个时点
打印 tie 网络与两个子模块复位引脚**的值**（上一轮我只判了"不是 X"，**没打印值**——这一步补上）。

## 1. 实测

```
PROBE after_reset_release HFSNET_124=1 rstn_calib=0 rstn_srm=0 calib_clk=1 HFSNET_119=0 busy=0 done=0 total=0 start_seen=0
PROBE before_start        HFSNET_124=1 rstn_calib=0 rstn_srm=0 calib_clk=1 HFSNET_119=0 busy=0 done=0 total=0 start_seen=0
PROBE after_start         HFSNET_124=1 rstn_calib=0 rstn_srm=0 calib_clk=1 HFSNET_119=0 busy=0 done=0 total=0 start_seen=0
PROBE after_6_decisions   HFSNET_124=1 rstn_calib=0 rstn_srm=0 calib_clk=1 HFSNET_119=0 busy=0 done=0 total=0 start_seen=0
PROBE late                HFSNET_124=1 rstn_calib=0 rstn_srm=0 calib_clk=1 HFSNET_119=0 busy=0 done=0 total=0 start_seen=0
```

| 观测量 | 值 | 含义 |
|---|---|---|
| `HFSNET_124`（无驱动的常量根） | **1** | 解析成了逻辑 1 |
| `HFSNET_119`（`HFSINV_6951_589` 的输出） | **0** | 反相后为 0 |
| `dut.u_calib_ctrl.rst_n` | **0** | **低有效复位被持续拉低 ⇒ 复位常驻** |
| `dut.u_srm_residue.rst_n` | **0** | **同上** |
| `calib_clk` | 1（在跑） | 时钟**是**在跑的，所以问题不在时钟 |
| `busy / done / total_count / dec_run` | 全 0 | **两个块从未工作** |

**⇒ 交付的布线后网表在仿真里，把 `u_calib_ctrl` 与 `u_srm_residue` 永久按在复位态。**
顶层 `rst_n` 端口在网表里未被使用（此前已证），两个块的复位只来自那条**网表没有定义值的**
tie 链：`HFSNET_124 → HFSINV_6951_589 → HFSNET_119 → rst_n`。

## 2. 更正我此前的一个推断

第 11 轮我据"版图 `SN` 接 VDD"推断 tie 根应为**逻辑 0**（反相后得 VDD）。
**本轮实测相反**：根解析为 **1**，反相后得 **0**，于是 `rst_n = 0`。
**那条推断作废**——当时的推理方向对，取值猜错了，**现在有测量**。

## 3. 这件事意味着什么（严格按证据说）

| 可以说的 | 证据 |
|---|---|
| **交付的网表按原样做门级仿真，主功能不可能被激励起来** | 上述 5 个时点的 `rstn_*=0`、`busy/done/total=0` |
| **被核查方那次 GLS 不可能发现功能是否正常** | 那次 TB 无 PASS/FAIL，且打印 `calib_done=0`；本轮的机制说明它**必然**是 0 |
| 顶层 `rst_n` 端口对这两个块**不起作用** | 网表里 `rst_n` 端口未被使用 + 实测 `rstn_*=0` 不随它变化 |

| **不能**说的 | 原因 |
|---|---|
| 「硅片也是死的」 | 仿真里的取值由**无驱动网的解析行为**决定；版图侧我没测到 `rst_n` 的实际连接，**不下结论** |
| 「这是设计逻辑错误」 | 这是**网表交付缺陷**（常量根未写出），不是 RTL 逻辑问题——RTL 侧 `.rst_n(rst_n)` 连接是正确的 |

## 4. 与前几轮的关系

- 第 3 轮我报"20 个输出 + 4 个内部点无 X、判定 `NO_X_ON_PROBED_POINTS`"。
  **那条仍然成立**，但它只说明"没有 X"，**没有说明功能在跑**——本轮补上了值，才看到复位常驻。
  **这正是"只做无 X 检查"会漏掉的东西。**
- 第 4 轮 tie 对照"两值无差异"现在有了新解释：**两个值下 `rst_n` 都是 0**（因为差异不在被我 force 的那 8 个端口上，而在 `HFSNET_124`）。
  ⇒ 那次对照要重做，**force 必须打在 `HFSNET_124` 上**。
