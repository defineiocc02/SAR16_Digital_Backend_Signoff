# 独立核查 V2 第十轮：**SRM 计数核对闭环**（预测被证实 + 偏差被算清）

**跑于** 2026-09-19　**产物** `/tmp/v2rtl/`（`tb_ref.sv`、`build.log`、`run.log`）

---

## 1. 先做一个可判真假的预测

上一轮观测到：复位释放后**先等 200 ns** 再送 decision，只收到 **21** 个且 `count_shortfall=1`；
去掉那 200 ns 后理论上应能收满。

**预测**：`200 ns ≈ 20 个 clk 周期`，正好吃掉 `STALL_CYCLES=64` 看门狗预算的约 1/3，
使最后一个 decision 被截掉。**⇒ 去掉等待应得到 `total_count=22 / shortfall=0`。**

## 2. 实测：预测**证实**

```
REF_STATE    shortfall=0 stalled=0 residue_valid=1
REF_OK       total_count = 22          ← 与预测一致
REF_MISMATCH ones_count  got=7 want=8
```

**`total_count = 22`、`count_shortfall = 0`** —— 看门狗门限的推断成立，
之前那个"差一个"确实是我的激励时序问题。

## 3. `ones_count = 7` 也**不是错**：接受窗口偏移一位

我的激励序列是 `f(i) = (i mod 3 == 0)`，i = 0…21。
若设计接受的是 **f(1)…f(22)**（武装后多一个 `dec_clk` 沿的延迟），则：

```
#{i ∈ [1,22] : i mod 3 == 0} = 3, 6, 9, 12, 15, 18, 21  →  7 个
```

**实测 = 7，与"窗口偏移一位"的独立计算逐位吻合。**

| 量 | 实测 | 独立计算 | 一致 |
|---|---|---|---|
| `total_count` | **22** | 22（无 shortfall） | ✅ |
| `count_shortfall` | **0** | 0 | ✅ |
| `ones_count` | **7** | 接受窗口 f(1)…f(22) 的 1 的个数 = **7** | ✅ |
| `residue_valid` | 1 | 发布结果 | ✅ |

**⇒ SRM 残差估计器的决策计数器与独立计算的期望完全吻合。**
这是本次独立核查拿到的**第一条完整闭环的正向功能结论**。

## 4. 这条结论的边界（严格按证据）

| 可以说 | 不能说 |
|---|---|
| **SRM 计数逻辑（判决计数 / 1 的计数 / 短样本自报）与独立期望一致** | 「整个数字核功能正确」——本轮只覆盖了 SRM 估计器的计数路径 |
| 设计在样本不足时**主动自报** `count_shortfall`，是正确行为 | `residue_o` 的数值换算正确——**尚未核对**（需读 LUT 映射） |
| **RTL 层**逻辑正确 | **交付网表**正确——第 5–8 轮已证它驱动不起来 |

## 5. 到目前为止，"功能实现了吗"的完整答案

**分三层，每一层都有独立证据**：

| 层 | 结论 | 证据 |
|---|---|---|
| RTL 逻辑 | **SRM 计数路径核对通过** | 本轮（V2 第十轮） |
| RTL ↔ 交付网表 | **逻辑等价**（1157 passing / 0 failing） | V1 |
| 交付网表可否被外部驱动 | **不能**：复位无定义（第 5 轮对照）+ 主状态机不前进（第 8 轮） | V2 第 5–8 轮 |

**⇒ 逻辑实现了，等价性成立，但交付的网表本身无法证明它实现了。**
问题不在算法，在**网表交付**。
