# 独立核查 V2 第八轮：决策域被"武装"了，但主状态机一动不动

**跑于** 2026-09-19　**产物** `/tmp/v2i/`（`tb_hold.sv`、`build.log`、`run.log`）
**做法**：正确的复位序列（根 1 → 根 0）之后，把 `srm_start` **持续拉高 1 µs**，每 100 ns 采样。

---

## 1. 实测

```
HLD reset_asserted  t=320000  rstn=0 start_pin=0 state=000 go_tgl=0 busy=0 dec_run=0
HLD reset_released  t=420000  rstn=1 start_pin=0 state=000 go_tgl=0 busy=0 dec_run=0
HLD start_held      t=520000  rstn=1 start_pin=1 state=000 go_tgl=0 busy=0 dec_run=1   ← dec_run 起来了
HLD start_held      …（连续 10 次采样，state=000 go_tgl=0 busy=0 dec_run=1 完全不变）
HLD start_low       t=1620000 rstn=1 start_pin=0 state=000 go_tgl=0 busy=0 dec_run=1
HLD consume_hi      t=1820000 rstn=1 start_pin=0 state=000 go_tgl=0 busy=0 dec_run=1
HLD late            t=3820000 rstn=1 start_pin=0 state=000 go_tgl=0 busy=0 dec_run=1
```

| 观测 | 值 | 含义 |
|---|---|---|
| `start_pin` | 1（持续 1 µs） | **start 确实送到了块边界** |
| **`dec_run`** | **0 → 1** | **clk 域 → dec_clk 域的 toggle 握手真的走通了** ⇒ `go_tgl` 的寄存器**被时钟打过** |
| `state` | **恒为 000（S_IDLE）** | **主状态机一步都没走** |
| `busy` | 恒 0 | 与 `state` 停在 S_IDLE 一致 |

## 2. 这一轮把问题又收窄了一层

**已经排除**：X（本轮 `dec_run` 干净地 0→1）、复位（复位序列生效）、
`start` 通路（`start_pin` 跟随）、时钟存在性（`go_tgl` 被时钟打过）、
握手同步（`dec_run` 被武装）。

**剩下的事实**：**同一个模块里，`go_tgl` 的寄存器被时钟打过，而 `state` 的寄存器没有。**
⇒ 最可能的是 **`state` 寄存器的时钟被单独门控**（综合插入的 `SNPS_CLOCK_GATE_*`），
而那个门的使能没有被拉起。**这是候选解释，本轮没有验证**（没有打印时钟门的 `EN`/`ENCLK`）。

## 3. 对"功能实现了吗"的独立回答（到目前为止）

**没有证据表明功能被实现过；而且有证据表明这份网表按原样无法被外部人驱动到工作状态。**

链条（每一步都有本轮或前几轮的实测）：
1. 交付网表对两个最大子模块**没有定义复位**——复位来自一条网表没有写出值的 tie 根
   （第 5 轮对照：根 1→复位常驻，根 0→复位解除）；
2. 必须把那条根当**复位序列**驱动，否则触发器停在 X（第 7 轮：`go_tgl` x→0）；
3. 即使复位正确、`start` 持续拉高 1 µs，**决策域被武装但主状态机不前进**（本轮）。

⇒ **三者叠加的结果是：这份网表在门级仿真里跑不到能出结果的状态。**
这也解释了被核查方那次 GLS 为什么只能产 SAIF、且 `calib_done` 必然是 0——
**它没有能力发现功能是否正常**。

**仍然不能说**的：硅片是好是坏。以上全部是**网表**行为；版图侧 `rst_n` 的真实连接我没有测。
