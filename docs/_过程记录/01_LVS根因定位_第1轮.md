## 0. 一句话结论

被打断方把 LVS 的端口问题判为"已解决（232=232）"，**实测不成立**。
逐名对账的结果是：源网表 232 个端口，版图 183 个，**51 个端口在版图里不成立、另有 2 个凭空多出**；
其中 **50 个是接口本身的退化端口**（常量绑定 + 输出对输出别名），**第 51 个 `rst_n` 是真缺陷**
（复位输入引脚落在电源轨上，被提取器并进 VDD）。

## 1. 硬证据一：端口账（逐名，工具无关）

用自写 SPICE 端口解析器（续行是**行首** `+`）对 `calibre/lvs/sar16.cdl` 与
`calibre/lvs/svdb/sar_digi_paper_core.sp` 的顶层 `.SUBCKT` 逐名比对：

```
source top ports : 232        layout top ports : 183
source-only : 51              layout-only : 2  (VDD, VSS)
232 − 51 + 2 = 183   ✓ 完全闭合
```

51 个 source-only 的构成：

| 类别 | 个数 | 说明 |
|---|---|---|
| `weight_rd_data[0..29]` | **30** | 顶层全部 `assign 1'b0` 绑死 → 版图里 30 个引脚同为 VSS → 提取器并成 1 个网 |
| `srm_residue_o[9], [11..29]` | **20** | 网表里是输出对输出的别名 → 21 个端口其实是同 1 个网 |
| **`rst_n`** | **1** | **真缺陷**，见 §2 |

**"232 − 29 − 20 = 183" 这个算式精确成立** —— 也就是说 Calibre 报的 183 不是"归并机制未知"
（被打断方 v4.3 文档把它列为遗留项），**它是 50 个退化端口的算术结果**。

## 2. 硬证据二：`rst_n` 被并进 VDD（本轮新出现，上一轮没有）

### 2.1 提取器的原话（本轮）

`calibre/lvs/lvs.rep.ext`：

```
WARNING:  Short circuit - Different names on one net:
          Net Id:  103
          (1)  name  "rst_n"  at location  (408.54,0.3575)  on layer  62 "M2"
          (2)  name  "VDD"    at location  (425,428.1)      on layer  62 "M2"
          The name "VDD" was assigned to the net.
```

**提取网表的顶层 `.SUBCKT` 里已经没有 `rst_n` 这个名字**（`grep rst_n` 零命中）。

### 2.2 上一轮没有这事（对照）

| | 短路组数 | 内容 | 端口数（提取网表顶层） |
|---|---|---|---|
| `lvsA.rep.ext`（07:25，round-3 前） | 2 | `srm_residue_o[9..29]`、`weight_rd_data[0..29]` | 204 |
| `lvs.rep.ext`（18:14，交付轮） | 3 | 上述两组 **+ `rst_n`/`VDD`** | 183 |

→ **`rst_n`↔VDD 是本轮新增的**，不是历史遗留。

### 2.3 几何复现（本机自写 GDS 解析器，不依赖任何 EDA 工具）

交付 GDS 顶层 cell `sar_digi_paper_core` 内：

```
label rst_n  layer 62(M2) at (408.540, 0.357) um 下，压着两组几何：
     layer 61 (M1)  bbox (0.000,-0.400)-(429.660,0.400)   429.660 x 0.800   ← 最底那条整宽标准单元电源轨
     layer 62 (M2)  bbox (408.430,0.000)-(408.680,0.715)    0.280 x 0.715   ← rst_n 自己的引脚体
```

**那条底轨是 VDD**，不是推测：电源轨与条带的过孔分布严格交替，且

```
rail#0  y=-0.40..0.40    via at strap x=425.000  ->  该条带带着 "VDD" 标签
rail#1  y= 4.64..5.44    via at VSS strap
rail#2  y= 9.68..10.48   via at VDD strap      ...严格交替
```

### 2.4 232 个引脚全都摆在边界上、且都压在边界结构上

对 234 个标签逐个做"标签锚点落在哪些图形里"的普查：

```
标签锚点分布：下边界 58、左边界 58、右边界 58、上边界 60、内部 0
下边界 58 个信号引脚**每一个**的引脚体都是 (x±0.14, 0..0.715)，
                          全部与底轨 y=-0.400..0.400 在 y=0..0.4 区间重叠
```

→ 这不是"某一个引脚没放好"，**是引脚摆放策略本身把引脚放在了电源结构上**。

### 2.5 唯一性是真实的：`rst_n` 的引脚体里没有过孔

```
calib_overrange_bits[18]  stub (57.940,0,58.220,0.715)  via: (58.08,0.56) ×2, (58.08,0.61)
dac_n_force[7]            stub (131.200,0,131.480,0.715) via: (131.34,0.56)
dac_n_force[17]           stub (203.800,0,204.080,0.715) via: (203.94,0.56) ×2
dac_n_force[19]           stub (218.980,0,219.260,0.715) via: (219.12,0.56)
rst_n                     stub (408.400,0,408.680,0.715) via: 无
```

**结论（按证据强度分层）**：

- **确证**：交付 GDS 里 `rst_n` 这个端口在提取网表中不存在，其标签所在网被命名为 VDD；本轮新增。
- **确证**：`rst_n` 引脚体与一条**实测属于 VDD 网络**的电源轨在几何上重叠。
- **确证**：`rst_n` 引脚体内没有过孔（邻居引脚有）。
- **未闭合**：连接是"引脚体经过孔短到轨"（则复位网真的短到 VDD），还是"引脚体悬空、标签被提取器按位置挂到了下面的 VDD 轨"（则复位引脚根本没接上核心）。两者都是交付件的缺陷，修法相同；但**对外措辞必须区分**，不能说成已确证的短路。

## 3. 硬证据三：LVS 差异的量化

`lvs.rep`：`INCORRECT NETS` 共 **50** 条，头两条就是全部量级：

```
1  Net VDD   layout 15246  vs source 13747   (+1499)
2  Net VSS   layout 13999  vs source 13951   (+48)
3+ 其余 48 条多为 4v4 / 8v8 / 9v9 等"条数相同但被判不正确"的内部网
```

- 初始器件数：MN 25465 vs 25059（+406）、MP 25560 vs 25123（+437）；
  **经 Calibre 归并后** Total Inst 19372 vs 19366（**+6**）→ 器件记账不是主要矛盾。
- `missing instance`（版图有、源没有的器件）**53 处 / 32 个 DISC 条目**，全是单个 `MN(N18)`/`MP(P18)`，
  分散在 `X0/X438`、`X0/X435`、`X4/X431` 等各处的单元内部。
- `no similar net` 295 处。

**⚠️ 一条被我自己的实测否掉的假设**（写下来防止后人重犯）：
我一度认为 `+1499` = 复位网的扇出被并进 VDD。**实测 `rst_n` 在源网表里的出现次数只有 57（CDL）/ 60（网表）**，
与 1499 差 25 倍。**该假设作废。`+1499` 的来源本轮未归因。**

## 4. 机制：为什么这一轮才炸

| 环节 | 位置 | 内容 |
|---|---|---|
| 引脚摆放 | `fc_pnr_paper_core.tcl:564` | `place_pins -self` → `block ports: 232 / pins created: 232`，**全部摆到边界** |

enclosing analog top.` —— **round-3 把电源网格搬进块内时，没有同步把信号引脚让开。**

## 6. 本轮我自己的三个解析器 bug（都曾产出"像结论的错数"）

1. **GDSII 记录号错位一位**：`0x19` 是 `STRING` 不是 `MAG` → 第一版报"234 个 TEXT 但 0 个标签"
   （正是被打断方记忆里警告过的同一个坑）。
2. **`XY` 记录按 8 字节/点算**（应为 4 字节/整数 ×2）→ `struct.error`。
3. **SPICE 续行方向搞反**（续行是行首 `+`，我按行尾找）→ 报"0 个端口、rst_n 不存在"。
   另外 `s.upper().startswith(".SUBCKT " + top)` 拿小写 `top` 与大写串比 → 又报 0。

**共同点：错误都发生在"解析器自己"，而输出看起来像审计结论。** 最终数字全部用
"双口径 + 可人工复核的 `Select-String`/`awk`"确认后才引用。
