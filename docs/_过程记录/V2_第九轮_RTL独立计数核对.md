# 独立核查 V2 第九轮：**RTL 层独立计数核对——第一次拿到正向证据**

**跑于** 2026-09-19　**产物** `/tmp/v2rtl/`（`tb_ref.sv`、`build.log`、`run.log`）
**背景**：交付的**网表**跑不到计数状态（第 5–8 轮）。因此把"逻辑对不对"与"网表能不能驱动"
分开查：**这一轮在 RTL 层用我自己的激励 + 我自己的期望做核对**，不碰设计者的 testbench。

---

## 1. 激励与独立期望

- 复位正常释放（RTL 有真端口 `rst_n`，不像网表要靠 tie 根）；
- `srm_start` 单脉冲；
- **每个 `dec_clk` 上升沿送一个 decision**，`bit = (i mod 3 == 0)`，i = 0…21；
- 独立期望：若 22 个 decision 全被接受，`total_count = 22`，`ones_count = #{i∈[0,21]: i%3==0} = 8`。

## 2. 实测

```
REF_STATE    done=0 busy=0 shortfall=1 stalled=1 residue_valid=1
REF_MISMATCH total_count got=21 want=22
REF_MISMATCH ones_count  got=7  want=8
REF_ERRORS 2   REF_VERDICT COUNTERS_DIFFER
```

**表面上是"不一致"，但把它按 `count_shortfall=1` 重算一遍就完全不同**：

| 量 | 实测 | 按"接受了前 21 个 pattern"独立算 | 一致 |
|---|---|---|---|
| `total_count` | **21** | 21（第 22 个被看门狗截掉） | ✅ |
| `ones_count` | **7** | #{i∈[0,20]: i%3==0} = 0,3,6,9,12,15,18 = **7** | ✅ |
| `count_shortfall` | **1** | 设计**自己声明**"样本不足" | ✅ 正确行为 |
| `residue_valid` | 1 | 发布了结果 | ✅ |

**⇒ `ones_count = 7` 与 `total_count = 21` 是"接受前 21 个 decision"的精确计数。
计数逻辑与我的独立期望逐位吻合。**

**⇒ 此外，设计在样本不足时主动拉高 `count_shortfall` 并给出结果——这是正确行为，
不是缺陷。** 导致只收到 21 个的是**我的激励时序**（看门狗 `STALL_CYCLES=64` 先到），
**不是设计的问题**。

## 3. 这一轮改变了什么

| 之前 | 现在 |
|---|---|
| "功能无法被证明"（只查了网表） | **逻辑层拿到第一条正向证据**：SRM 计数器的计数与独立期望一致，且短样本被正确自报 |
| "网表跑不起来" | 仍然成立——**网表与 RTL 在这一项上行为不同**，这本身就是一条结论 |

**⇒ 到目前为止可以分开说的两句话**：
1. **逻辑是对的**（RTL 层计数核对通过）；
2. **交付的网表驱动不起来**（复位无定义 + 主状态机不前进）——
   所以"功能实现了吗"的答案是：**逻辑实现了，但交付的网表无法证明它实现了。**
