# 独立核查 V1-a：端口账**闭合**（178 vs 146 从来不是缺口，是我在比两个不同口径）

**方法**：把交付网表自己的顶层端口表**位展开**（`tools/v1a_ports.py`），
再与 Formality 的比对点分类、LVS 的端口数逐项对齐。

---

## 1. 位展开结果

| 量 | 值 |
|---|---|
| 顶层端口**名字** | **31**（输入 11 / 输出 20） |
| 位展开输入 | **30** |
| 位展开输出 | **146** |
| **位展开合计** | **176** |

## 2. 三张表一次对齐（每一格都有来源）

| 量 | 值 | 来源 | 是否吻合 |
|---|---|---|---|
| 位展开**输入** | **30** | 我的位展开 | Formality 日志 `30 Matched primary inputs, black-box outputs` **= 30** ✅ |
| 位展开**输出** | **146** | 我的位展开 | Formality `1157 Passing compare points (Port 146 + DFF 1011)` 里的 **Port = 146** ✅ |
| 位展开**合计** | **176** | 我的位展开 | 第 2 轮的接口收窄算术 `232 − 36 − 20 = 176` **精确成立** ✅ |
| LVS 版图端口 | **178** | `lvs.rep` | **176 + VDD + VSS = 178** ✅ |

**⇒ 三个数字全部对上，而且每一格都指向同一个物理意义。**

## 3. 所以 V1-a 的答案是

**`178` 与 `146` 不是同一个口径**：

- **`146` 是位展开的"输出端口"数** —— 也正是 Formality 的 `Port` 比对点数
  （输入端口在 Formality 里走的是 `Matched primary inputs` 那一类，不重复计入 `Port`）；
- **`178` 是 LVS 的版图端口总数** = 176 个信号位 + **VDD + VSS**（版图有具名电源端口）。

**⇒ 当年我把它记成"端口账 178 vs 146 未闭合"，是把两张不同口径的表当成了同一张。
这是个假缺口。**

## 4. 顺带确认的独立事实

- 交付网表顶层**只有 31 个端口名**，没有多余的、也没有少的；
- `raw_bits_i[19:0]`（20）、`w_wr_data[29:0]`（30）、`srm_residue_o[9:0]`（10）
  三个宽口的位宽与第 2 轮接口收窄后的设计意图一致；
- **没有任何宽度是"未取得"或可疑的**。

## 5. V1-a 状态

| 项 | 状态 |
|---|---|
| 178 vs 146 的差额 | **完全解释**（不同口径 + VDD/VSS） ✅ |
| 端口位展开总数与接口收窄算术 | **一致（176）** ✅ |
| 遗留 | **无** |

**⇒ V1-a 关闭。** 它是本次核查里第一个"以为有缺口、其实是口径问题"的项——
与 §2 那几条真实缺陷相比，这一条属于**交付文档口径未写明**，
而不是交付件本身有问题（但同样值得写清楚）。
